# Seven-minute reproducible demo

Prepare `make db-up`, `make fetch-sample`, `make etl`, `make fetch-weather`, `make analyze`, and measured benchmarks before class. Open `make dashboard` and the generated report. If external services fail, show the persisted failure artifact and use `make smoke`; identify synthetic engineering evidence explicitly.

1. **0:00–1:00 — source and question.** On Overview, show the official sample dates and suffix rule. Select February, HPD and BRONX (253 sampled requests), then drag the timeline: cards, charts and “What this view tells us” should change together. Reset the brush and filters. Explain daily snapshots versus reconstructed historical streaming, fixed follow-up, right censoring and sample limitations. The current download offers 2025Q1 only; selectors do not download other years.
2. **1:00–2:15 — actual stream.** Run `make stream-demo` (or the two-terminal producer/continuous consumer commands in README). Show producer flags, current state, saved Cox predictions and model version. The bounded demo intentionally logs one expected post-commit failure.
3. **2:15–3:00 — recovery.** Open streaming_metrics.json: fault_after_commit_observed, final_database counts, second_restart_unchanged and quarantine. Explain event uniqueness, version-protected CLOSED state, same checkpoint and separate fixture/official schemas.
4. **3:00–4:15 — survival and prediction.** Show filtered KM curves, confidence intervals, group sizes and censoring; click a legend to highlight groups. Distinguish the selected creation cohort from the saved March temporal holdout and training cutoff. Compare saved Cox and KM baseline C-index with actual denominators. Run CLI prediction. A null90-day probability is unsupported follow-up, not zero.
5. **4:15–5:15 — seasonality/weather/capacity.** Change the cohort and weather variable to show the recalculated unadjusted exploratory association; legend highlights do not change its denominator. The saved scientific report retains the original heat-specific month-controlled analysis. Open capacity_scenarios.csv, observed KM versus simulated baseline and calibration_status. Capacity results use their saved cohort. Failed calibration means no precise improvement claim; uplifts are scenarios, not hiring effects.
6. **5:15–6:15 — scalability evidence.** Show raw runs.csv, real registered Worker/executor attestations and all statuses. Distinguish local[2]1x/10x/100x synthetic workload from separate1/2/4/8Worker experiments. Negative speedup is valid. State one physical host and resource changes.
7. **6:15–7:00 — reproduction and limitations.** Show pytest.xml, smoke.json, README/Makefile, fixed dependency lock, source checksums and config. Identify incomplete or blocked checks from IMPLEMENTATION_STATUS.md. No claim is made for an unexecuted clean-machine build or production deployment.
